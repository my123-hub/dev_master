## 1. 项目概述

### 1.1 项目背景

STK本然家居（以下简称"STK"）作为家居品牌企业，目前缺乏统一的线上品牌展示与获客渠道。为树立品牌形象、展示产品与实景案例、传递企业实力（发展历程、品牌理念、人才招聘），并获取潜在客户线索（到店预约、在线留言），特建设企业官网。

### 1.2 系统组成

本项目建设**两套子系统**：

1. **前台展示系统（企业官网）**：面向访客（C端消费者、B端客户、求职者），展示品牌、产品、案例、新闻、招聘、服务支持等信息，并提供在线预约/留言的留资入口。
2. **后台管理系统**：面向 STK 内部运营人员（管理员、内容编辑），统一维护前台所有展示内容（产品、案例、新闻、招聘、页面内容、首页配置、门店、FAQ 等），并处理访客留资数据（预约、留言）。

### 1.3 关键设计原则

- **内容驱动**：前台所有展示内容均由后台维护，支持运营人员自助更新，无需开发介入。
- **留资闭环**：在线预约、在线留言为两条核心留资链路，数据实时进入后台并支持跟进状态管理。
- **品牌调性**：整体视觉遵循"极简、高级、大气"风格，突出产品与空间质感。

## 2. 项目目标

| 编号 | 目标 | 衡量方式 |
|------|------|---------|
| G1 | 建立统一的线上品牌形象窗口 | 官网正式上线，全渠道可访问 |
| G2 | 完整展示产品线与实景案例，支撑 B/C 端客户决策 | 产品、案例内容 100% 可由后台维护 |
| G3 | 形成可追踪的留资转化链路 | 预约/留言数据进入后台，支持导出与跟进状态管理 |
| G4 | 支持招聘信息自助发布，降低招聘信息维护成本 | 招聘职位由后台自助发布/下线，前台自动同步 |
| G5 | 内容更新不依赖开发 | 运营人员经后台完成所有内容维护 |

> 说明：本项目**不做 SEO 优化**（按需求方确认），不追求搜索引擎收录指标。

### 3.1 范围内（本期交付）

|--------|---------|

### 3.2 非目标（Non-goals）

- ❌ 在线商城：不支持商品下单、购物车、在线支付、订单管理；
- ❌ 前台用户注册/登录/会员体系；
- ❌ 多语言版本（中英双语）；
- ❌ SEO 优化（TDK 元信息、sitemap、静态化、关键词策略）；
- ❌ 小程序 / App / 公众号 H5 版本；
- ❌ 在线客服实时聊天、视频直播；
- ❌ 门店线上预约核销、CRM / ERP 系统对接（预留扩展即可）。

> 以上为非目标项，若后续业务需要，可在二期规划中评估。

## 4. 整体技术架构

本项目整体技术栈按层次划分如下，所有选型兼顾**生产环境可用性**与**开发效率**，并支持后续平滑扩展。

### 4.1 技术选型一览

| 层次 | 技术选型 | 说明 |
|------|---------|------|
| 前端框架 | React 18+ | 组件化开发、生态丰富 |
| 前端构建工具 | Vite 5+ | 快速开发服务器与打包构建，HMR 热更新 |
| 前端样式（前台） | Tailwind CSS 3.x | 快速构建高端大气 UI，响应式设计 |
| 前端 UI 组件库（后台） | Ant Design 5.x | 成熟的企业级后台组件库 |
| 前端路由 | React Router v6 | SPA 页面路由管理 |
| 前端状态管理 | React Context / Zustand | 轻量级状态管理 |
| HTTP 客户端 | Axios | 与后端 API 通信 |
| 后端框架 | FastAPI | 高性能异步 Python Web 框架 |
| ORM | SQLAlchemy 2.0 + Alembic | 数据库 ORM 及迁移管理 |
| 数据库（开发环境） | SQLite 3.x | 开发环境使用 SQLite，启动简单、无需单独安装数据库服务 |
| 数据库（生产环境） | PostgreSQL 16+ | 生产环境切换至 PostgreSQL，通过 SQLAlchemy 同一 ORM 无缝切换，无需修改业务代码 |
| 认证鉴权 | JWT（JSON Web Token） | 后台 API 鉴权 |
| 文件存储 | 本地文件系统 / OSS | 图片和静态文件存储 |

### 4.2 关键架构说明

- **双库无缝切换**：开发与生产共用一套 ORM 代码，通过 `DATABASE_URL` 环境变量（`sqlite:///./app.db` 或 `postgresql://user:pass@host:5432/db`）切换，业务代码无感知；详见 §10 数据库设计。
- **前后端分离**：前端构建产物由 Nginx 静态托管 + 反向代理至 FastAPI；详见 §12.5 部署。
- **数据库迁移**：使用 Alembic 管理 schema 变更，开发与生产通过迁移脚本同步结构。
- **状态管理轻量化**：前台状态以 React Context 为主，复杂跨页面状态可用 Zustand；不引入 Redux 以降低复杂度。
- **认证鉴权**：后台基于 JWT，登录签发 token，接口统一拦截校验；前台公开接口不需鉴权。
- **文件存储可演进**：本期默认本地文件系统（`uploads/` 目录），架构层预留接入 OSS 的能力（详见 §10.1 设计原则）。

## 5. 用户角色

### 5.1 前台角色（访客）

| 角色 | 说明 | 核心诉求 |
|------|------|---------|
| C端消费者 | 有家装/家具购买意向的个人用户 | 了解品牌与产品、查看实景案例、预约到店、留言咨询 |
| B端客户 | 经销商、工程项目方、设计公司等 | 了解产品体系、企业实力、获取联系方式、留资洽谈 |
| 求职者 | 社会/校园求职者 | 查看招聘职位、岗位要求、联系方式 |

> 前台不设登录体系，所有访客以游客身份访问（按非目标约定）。

### 5.2 后台角色

| 角色 | 权限范围 | 说明 |
|------|---------|------|
| 超级管理员 | 全部权限 | 拥有后台所有模块权限，含系统管理（用户/角色/日志） |
| 内容编辑 | 内容维护类权限 | 产品、案例、新闻、招聘、内容、首页配置、服务支持、预约、留言的管理；**无系统管理权限**（不可管理用户、角色、查看操作日志） |

> 权限为**角色-权限点**模型，按功能模块细分权限点，便于后续扩展更多角色（如"招聘专员"仅管招聘模块）。

## 10. 数据库设计

### 10.1 设计原则

- 数据库：**开发环境 SQLite（零配置、轻量，随项目启动即用）；生产环境 PostgreSQL 16+（功能强、并发高）**。通过 SQLAlchemy + 环境变量 `DATABASE_URL` 切换（`sqlite:///app.db` / `postgresql://user:pass@host:5432/db`），业务代码无感知；
- 所有业务表含公共字段：`id`（主键）、`is_activate`（1激活/0禁用）、`created_at`（创建人→sys_user.id）、`created_date`（创建时间）、`updated_at`（修改人→sys_user.id）、`updated_date`（修改时间）；
- 删除策略：以 `is_activate`（1激活/0禁用）为主，禁用即等效软删除，关键业务数据可追溯；
- 通用"内容页"表：关于STK、品牌介绍、售后政策等单页富文本内容统一存储于 `page_content` 表，按 `content_type` 区分，减少表数量；
- 多图/参数类数据（图集、规格参数、空间标签）采用 JSON 字段存储（SQLAlchemy JSON 类型，SQLite 与 PostgreSQL 均支持），简化模型；
- **双库兼容注意事项**：字段类型统一使用跨库通用类型（Integer/String/Text/Boolean/DateTime/JSON/Numeric），避免依赖数据库专有类型；公共字段（id/is_activate/created_at/created_date/updated_at/updated_date）在两端表现一致；SQL 全部由 ORM 生成，不手写方言级 SQL。

| 编号 | 需求 | 说明 |
|------|------|------|
| NFR-06 | 认证安全 | JWT 认证；密码 bcrypt 加密；登录失败限流 |
| NFR-07 | 权限安全 | 后端每个接口校验权限（权限点在服务端强制执行，前端仅隐藏入口） |
| NFR-08 | 输入安全 | 参数校验（Pydantic）；防 SQL 注入（ORM 参数化）；富文本 XSS 过滤（入库前清洗） |
| NFR-09 | 上传安全 | 文件类型白名单（jpg/png/webp）、大小限制（≤5MB）、随机文件名、禁止可执行文件 |
| NFR-10 | 隐私合规 | 预约/留言表单展示隐私提示；个人信息仅用于业务联系，不做非法使用 |
| NFR-11 | 接口限流 | 前台表单提交接口限流，防恶意刷单 |
| NFR-12 | 传输安全 | 正式环境启用 HTTPS |

### 12.3 兼容性与可用性

| 编号 | 需求 | 说明 |
|------|------|------|
| NFR-13 | 浏览器兼容 | Chrome / Edge / Firefox / Safari 最新两个大版本；移动端主流浏览器 |

| NFR-15 | 可访问性 | 基础无障碍（图片 alt、按钮语义化） |
| NFR-16 | 容错 | 前台接口失败有兜底 UI（骨架屏/重试/空状态），不白屏 |

## 13. 设计规范

> 设计基调：**极简、高级、大气**。参考蓝鸟官网的克制感，但更强调留白与现代感。

### 13.1 视觉规范

| 维度 | 规范 |
|------|------|
| 主色调 | **墨绿色系为主色**：深墨绿（如 #0F3D2E，呼应自然与高端质感）用于品牌主色/标题/导航；**整体背景采用浅色调**（如浅米白 #FAF8F5、浅灰绿 #F4F7F5），与墨绿色系协调统一 |
| 辅助色 | 低饱和灰（#9E9E9E）用于正文/弱化信息；点缀色可选浅墨绿（如 #6FA088，墨绿同色系浅调），仅用于 CTA 按钮与关键数字 |
| 字体 | 中文：思源黑体 / 系统字体栈；标题加宽字距（letter-spacing），正文行高 1.6-1.8 |
| 图片风格 | 大图、留白、真实场景摄影为主；产品图统一背景（纯白/浅灰棚拍感） |
| 布局 | 大区块留白（页面上下留白 ≥ 80px），卡片式内容区，栅格 12 列 |
| 动效 | 克制的淡入淡出、图片 hover 缩放（≤1.05），避免花哨动画 |
| 圆角 | 卡片圆角 8-12px；按钮圆角 4-6px（克制） |
| 阴影 | 轻阴影（0 2px 12px rgba(0,0,0,0.06)），避免重阴影 |

### 13.2 后台设计规范

  - 采用 Ant Design 5.x 默认设计语言 + 品牌色微调；侧边栏采用深墨绿（#0F3D2E）与前台品牌色呼应，内容区浅色调背景；
  - 左侧导航采用**可折叠手风琴式二级菜单**：父级菜单默认折叠，点击展开子项（▼ 箭头旋转指示），同组仅展开当前所在页父级、其余自动折叠；角色相关菜单（如系统管理）按角色显示/隐藏；
  - 表格密集但留白充足；表单统一 `Form + Modal/Drawer` 编辑模式；
- 富文本编辑器建议：wangEditor（中文生态好、轻量）。

## 16. 验收标准

### 16.1 前台验收

1. 前台所有栏目（首页/产品/案例/新闻/招聘/关于我们/服务支持）均可正常访问，移动端适配无错位；
2. 产品、案例、新闻、招聘、门店信息（上海旗舰店）、FAQ 等数据与后台维护一致，上下架/停用状态即时生效；
3. 在线预约、在线留言表单校验完整，提交成功有明确反馈，数据正确落库（后台可见）；
4. 全站无控制台报错，图片懒加载生效，404 页面可用。

### 16.2 后台验收

1. 超级管理员可管理全部模块；内容编辑仅能访问内容类模块，越权接口返回 403；
2. 所有列表支持分页/搜索/筛选；所有增删改操作有正确反馈；危险操作有二次确认；
3. 预约/留言支持状态流转与 Excel 导出；
4. 关键操作均记录操作日志，可按条件查询。

### 16.3 系统验收

1. `docker compose up -d` 一键启动，前后端与数据库连通正常；
2. 正式环境 HTTPS 可访问；上传图片类型/大小限制生效；
3. 接口有 Swagger 文档；数据每日自动备份。
